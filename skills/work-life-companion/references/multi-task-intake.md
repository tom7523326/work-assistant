# Multi-Task Intake（多任务一次性入库的处理范式）

用户经常一次扔 3-7 条不同领域的事项。这是高频场景。

## 反模式（不要做）

❌ 逐条问澄清："第一件事的截止日期是？" "第二件事是工作还是生活？"
❌ 问是否要砍除："这么多事要不要砍 1-2 件？"
❌ 提前总结："你这周事很多，建议..."
❌ 长篇分析每件事的优先级矩阵

## 正确模式（一次性吞下）

### Step 1: Verify-before-Reason 极简版

如果信息含糊，**只对关键含糊点提问 1-2 个**。其它**用最朴素假设 + notes 标"待澄清"**。

例：用户说"另外周日要做 X"，没说几点 → 默认 22:00 + notes 标"具体时间待定"。

### Step 2: 分批字段判断

对每条事项快速判断：

```
domain：family/work/finance/life/growth
priority：P0/P1/P2/P3
deadline：从用户语境推
next_action_5min：必须具体可动作
有依赖关系吗？→ 决定要不要合并
有 SOP 严格性吗？→ 写进 notes（如"24h 尿蛋白"严格时间窗口）
```

### Step 3: 一次写完

```python
new_tasks = [
    { ... },
    { ... },
    ...
]
d["待办"].extend(new_tasks)
p.write_text(...)
```

### Step 4: 简短确认 + 双刷

```
✅ 已入库 N 个新任务（T0NN ~ T0MM）
```

后跟最多 1-2 个**真值得提的观察**（不是建议）。

例：
> "✅ 已入库 5 个任务"
> "顺手提醒：周五（5/22）你已经有 3 件事（周丹饭局/西双版纳汇报/孩子生日），新加的 X 也在那天，密度高。"

**只是提醒，不强制建议改期**。

## 特殊场景

### 含医疗/财务/法律风险的事项

主动加风险提示（在 notes 里）。

例：
- 用户说"24h 尿蛋白" → notes 必须写完整 SOP（弃第一泡 / 闭区间 / 容器要求）
- 用户说"X 月还款" → notes 写"扣款账户末四位 + 余额最低需达 ¥X"
- 用户说"签合同" → notes 提示"对方主体/付款条款/违约责任 三件套"

### 隐藏依赖（任务间）

识别"看起来 N 件，实际 1 件"的模式，**主动合并**。

例（已发生过）：
- 电脑选型 + 大路灯 + 编程课 = "孩子学习装备升级"（1 个项目，4 个 sub_task）
- 招行还款 + 交行还款 + 公积金还款 = "本月还款余额守卫"（1 个守护任务，3 个余额检查 sub_task）

合并后：原 N 个任务标 cancelled + `_合并到`，新任务包含所有 sub_tasks。

### 跨领域批量场景

用户一次扔 6+ 件事时，看板会膨胀。但**不要主动减负**——用户没说让你砍，就完整入库。

减负是用户的判断，不是 AI 的越权。

### 模糊事项

用户说"另外，X 这事也得跟进"，没说细节：

- 入库一个**占位条目**：title 用用户原话简化，notes 标"待用户补充"
- 不主动追问 3 个细节问题（用户会自己补）

## 真实输出示例

用户输入：
> "1. 今天中午 11:45 健身  2. 下午梳理 X 平台  3. 选 AI 博主对标  4. 体检报告  5. 给爸妈买 AI 助手下周买"

正确响应模板：
```
[5 个新任务全部入库的 Python heredoc 代码块]

✅ 已入库 5 个新任务（T032~T036）

[简短观察 1-2 句]
- 健身: 你的固定节奏是 [grep 结果]
- AI 博主对标: 这是 KOL Phase1 的 #2 优先动作，建议先看 [3 个具体名字 + 推荐理由表格]
- 给爸妈买 AI 助手: 主流 4 款 + 我的推荐 + 最大坑（场景设计）

[结尾不追问，等用户继续]
```

## 关键心态

用户给信息的速度 > AI 处理的速度。**不要让用户等我澄清，直接吞下**。
等到全部入库后，再做轻量的横向观察。
