# Anti-Patterns（已踩过的坑）

记录所有真实犯过的错误。每条包含：错误现象 / 根因 / 防御机制。

---

## AP-001: 凭语感判断生活节奏（2026-05-20）

**错误现象**：
用户说"今天 11:45 健身"，我自动判断为"无氧"，并基于此推断"本周节奏被打乱"。

**事实**：
用户的节奏明确是「周一/三/五 有氧，周二/四 无氧」，今天周三应该是有氧。我没读 `数据/12_待办.json` 的 T007.training_plan_weekly 就凭印象答。

**根因**：
1. 工作记忆短，跨对话/跨日就模糊
2. 没把 Step 1 grep 记忆 当作强制 SOP

**防御机制**：
- 任何涉及"运动/饮食/家庭节奏"的回答前，**强制 grep**：
  ```bash
  grep -A3 -i "训练\|运动\|健身\|有氧\|无氧" 数据/12_待办.json
  grep -A2 -i "训练\|运动" _记忆/SOUL.md
  ```
- 如果 grep 不到就**主动问用户**，**不要瞎猜**

## AP-002: 把用户当 AI 入门学徒（2026-05-19）

**错误现象**：
推荐用户跑 hello_ai.py / 学 system prompt / 教 multi_turn 对话。

**事实**：
用户已经做出 53 个 Python 工程文件 + 自写 futu MCP + skill_evolution_loop + 真实下单的金融 agent。是 L4-L5 AI 工程师。

**根因**：
1. 没主动看用户已有项目目录
2. 默认假设"问 AI 学习的人 = 新手"

**防御机制**：
- 用户提到"我的工作文件"或给目录路径时，**立刻 ls + find**了解项目规模
- SOUL.md 已经标注"L4-L5 工程师"，**不要再走教学模式**

## AP-003: 决策疲劳轰炸（2026-05-19 用户明确反馈）

**错误现象**：
连续多轮回复都是"A/B/C 选一个？"，用户感觉在不停做选择。

**事实**：
用户要的是 **看到全貌自己判断**，不是被频繁询问。

**根因**：
1. 误以为"给选项 = 拖延症友好"
2. 没区分"真有决策点" vs "信息展示"

**防御机制**：
- A/B/C 仅在**真有不可逆决策**时用
- 信息呈现用**展示**而非**提问**
- 默认不结尾追问，用户想做就会说

## AP-004: 主动建议"砍掉 X"（2026-05-19 用户明确反馈）

**错误现象**：
看到用户多任务时主动说"建议砍掉 X 来腾出精力"。

**事实**：
用户明确表态："你不是让你都给我决策，最起码我在你这里一目了然能看到所有的待办"。

**根因**：
1. 把"产品经理思维"误用到对用户的服务上
2. 越界做"减法决策"

**防御机制**：
- **用户没说"帮我砍" → 绝不主动建议砍**
- 数据驱动 → **完整展示**，不替用户筛选

## AP-005: 把 todo 看板变成信息堆放场（2026-05-19 用户反馈"展示有点乱"）

**错误现象**：
18 个 todo 全部平铺，颜色/分组/层级都缺。

**事实**：
顶级 todo 产品（Things 3 / Linear / Notion）核心是 **信息分层 + 时间漏斗 + 颜色编码**。

**根因**：
1. 数据驱动设计第一版只追求"完整"
2. 没主动学习行业最佳实践

**防御机制**：
- 任何看板/视图设计 → 先想 3 个对标产品
- 信息减负优先于堆砌（合并依赖任务、归档过期、折叠长尾）

## AP-006: 写中文文件编码踩坑（2026-05-13 README.md 污染）

**错误现象**：
直接用 `echo "中文内容" > file.md`，结果生成 `ef bf bd` 替换字符的乱码文件。

**事实**：
shell 对中文 + 特殊字符的处理在 macOS 终端经常出 GBK/UTF-8 混乱。

**根因**：
偷懒用一行命令而不是 Python heredoc。

**防御机制**：
- **所有写入中文文件的操作**：Python + `encoding="utf-8"` + heredoc
- 写完用 `cat` 或 `head` 立刻验证编码

```python
# ✅ 正确
with open('file.md', 'w', encoding='utf-8') as f:
    f.write(content)

# ❌ 错误
# echo "中文" > file.md
# write_file_with_redirect "中文内容"
```

## AP-007: 不 Verify-before-Reason 直接下结论（2026-05-14）

**错误现象**：
用户截图发对话记录，我没逐行复述就分析"用户的优势在 X，短板在 Y"，结果完全把用户和 AI 角色对调，分析全错。

**事实**：
截图里"你"和"李姐"分得清，但我按"问号结尾 = 提问者"偷懒判断。

**根因**：
1. 偷懒：模式化推断 vs 仔细看
2. 没有"先复述再下结论"的强制 SOP

**防御机制**：
- 任何对话级 / 截图级 / 多源数据级分析：**先复述确认事实**
- 模板：
  ```
  我先复述确认（Verify-before-Reason）：
  | 项 | 用户原话 | 我的理解 |
  对吗？不对告诉我哪格。
  ```
- 用户挑战我时，**重新逐字读**，不要急着妥协

## AP-008: 总结刚才做的事浪费 token（高频）

**错误现象**：
做完一个任务后又用大段话"总结今天我们做了什么"。

**事实**：
用户刚做完，知道发生了什么。重复=浪费 token + 对话冗长。

**防御机制**：
- 操作完成后只回**简短确认**："✅ T0XX 已入库"
- 用户问"今天做了啥"才总结

## AP-009: 把虚构的事实当真说（2026-05-19 给用户做对话分析时）

**错误现象**：
分析用户和 AI 的销售对话时，我编造了"价格反复跳变 10→20→180"，实际"180"用户根本没说过。

**事实**：
我把"我的语感推断"当作"用户截图里的事实"。

**防御机制**：
- 引用用户话时**只能复述 100% 看到的内容**
- 不确定时说"我从截图里看到 X，不确定 Y 是不是也说了"
- 数字/日期/姓名等硬数据出现幻觉风险最高，**严格只引用确证的**
