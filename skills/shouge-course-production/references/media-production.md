# 媒体制作与审片

这里是Day13验证过的方法和易错点。参数先检查本期素材，再采用；新一期不要直接运行写死Day13的脚本。

## 源素材与版式

- 制作目标默认1920×1080、16:9、H.264/AAC；Day13统一25fps。保持像素宽高比1:1，按音轨最终长度对齐。
- 课件背景铺满画幅。相同画幅图直接适配；不同比例素材等比放大/轻裁时先检查标题、人物和字段有没有被裁。生成封面的独立重排要求与视频镜头的适配处理是两件事。
- 禁止把整个旧成片裁掉后整体放大来“消黑边”；回到课件、录屏和口播源重合成。旧 `prepare_compose.py` 的render生成底部164px黑带，不采用该布局。
- 不为字幕预留大片纯白或黑带；背景连续，字幕只在文字附近用轻底/描边。ASS设置与成片相同的PlayRes，Day13用52字号/下沿38作为参考，手机大小实看。

## 头像与课件清理

本人源先看首帧，选择能覆盖圆窗的正方形区域，再统一缩放、圆形mask和定位。不能在大灰圆里叠一个更小头像。圆窗和圆环必须共用中心/半径，边缘完整，不在不同页随机漂移。

Day13最终镜头配置：235px，左上角[1665,820]，中心[1782.5,937.5]，满幅1080p。这只是Day13历史参数；用户发布后截图已证明右下圆窗被抖音账号头像遮住，不再作为新一期默认位置。timeline旧notes中的225px和逐页对圈说明也已过时。

以后先试左下偏上：1920×1080画面左上角[72,790]、直径235px，矩形范围[72,790,307,1025]；统一初值位于assets/landscape-layout.json。圆环/头像共用中心，课件左下用连续背景留空间。该坐标只作试片初值，不是官方安全区，必须用本期各页和手机实际播放布局核验。Day14重新核对新源裁切和遮挡。用户允许轻微遮字，但按钮、关键数字与字幕仍须能理解；关键实操可关闭头像，出现时保持同一大小。

源课件如果已带旧灰圆、旧头像、白框和空白底栏，先在底板清理，再叠新头像。优先重新生成同风格页面；若局部修复，用相配纸纹/背景连续延展，避免用一大片纯白/单色新框挡旧框。Day13最终8补页修复脚本按页坐标采样，不能原封照搬到其他页。

先做至少一个2秒专项：讲解页、最复杂补页或密集操作；检查头像、圆环、底栏、字幕与边界后再全片渲染。

## 真实演示

实际操作录像保持输入→动作→结果顺序，关键结果留够观察时间。可以局部放大、跟焦和后期高亮；不要用静态终点截图替代功能发生。

Day13部分镜头裁[1560,796,315,140]后加100px教学浏览器框，以解释“Vibe Coding产物：网页工具”。这些数字是旧画面坐标，Day14用自己的可读区域。后期框不伪装真实地址/AI生成界面。

自动录像脚本只用于独立本地教学工程。用户已登录Chrome及外部账号通过当时可用的浏览器控制能力操作，不能因本地可用Playwright就绕过Chrome账户会话。

## 口播、剪切与字幕

保留HeyGen原始源。先核对实际读出哪些句子，漏句/错读记录清楚，再把已核验实际文本强制对齐到音轨。原稿在稿件中存在并不代表说过；字幕不偷偷补没读的句子。

使用同一剪切表同步截取数字人画面、声音和字幕；字幕重新基于最终音轨映射，切口避免切入单词/音节。ASR可能把Vibe Coding识别成webcoding，可疑词必须实际听查，不能只凭ASR判断发音错。

片头和实操生成音轨弃用。最终主声音仅使用已认可本人音轨；如加音乐，需本轮范围及可用素材依据，不自加盖过人声的音乐。

Day13旧157条字幕/4秒静默卡已经被130条精剪字幕取代。以最终SRT和最终时间轴为准，不再使用按原稿段数猜时长的方法。

## 渲染脚本参考与适配

Day13最终渲染器：`AI学习/内容/定稿/Day13/视频制作/二次修订/合成工具/render_fullframe.py`。

输入CLI：`--timeline --avatar --srt --out --work`；可选`--audio --avatar-crop --avatar-size --font-size --subtitle-margin --fps`。原脚本的FFmpeg、字体、浏览器框及资历补丁路径/内容写死本机或Day13；下期复制到本期合成工具再参数化，核对帮助和实现后执行，不能宣称通用脚本已就绪。

时间轴镜头含`start/end/path`；按需要使用`kind/source_time/crop/avatar/avatar_position/overlays/browser_frame/label/highlights`。路径指向本期真实素材，相邻镜头连续误差不超过1帧，所有帧时长按帧率取整。

Day13的 `record-day13.cjs`、`生成v7纸面底板.py`、旧对齐计划均可参考方法，但选择器、页坐标、固定10→4→3、路由和绝对路径必须替换。本期另列独立预期，不从页面自报结果复制期待值。

运行时按当前环境发现。曾验证本机缓存里有 ffmpeg、Python 和 small 模型；**该目录没有ffprobe**。不要把缓存路径或ffprobe可用写成永久保证。缺依赖先探测/选择已授权本地替代，不默认购买或安装付费组件。

## 审片证据

每一期留下以下结果，程序与人工结论分开：
1. 工程实测：主要流程、关键字段/数字、一个失败/例外、当前保存/刷新行为。
2. 文件/时间轴：视频与音轨时长相符、镜头连续、字幕无重叠或越界，导出格式正确。
3. 全片解码：用实际找到的FFmpeg读取最终文件并输出null，记录退出状态。探测元信息可用ffprobe（确实可用时）或FFmpeg等可靠本地读数。
4. 逐镜头视觉：每个不同页面至少一帧；所有补页；开头前几秒、结尾；每个切点前后；本人/字幕/关键按钮无异常。导出抽查图注明对应最终版本。
5. 手机平台预览：除缩小后的可读性，还检查抖音竖屏常规播放、横屏全屏、账号头像/点赞评论等控件显示时的遮挡。本人圆窗避开右侧控件，关键内容与字幕留可读空间；不能只靠干净的1080p大图判断。播放器围绕横屏视频显示的黑色区域与视频文件内嵌黑边分别记录，不因平台正常布局改变已定画幅。
6. 实际听审：关键术语、声音/口型、漏句、拼接残音、片头音轨；用户审看意见和已修结果。

自动化能证明结构和运行，不能证明头像身份、可读性、发音自然或课程可学。没听完整段就不写“全片听审通过”；没学员试用就写“作者自测”。失败项先修正，再重新检查受影响片段与最终输出。
