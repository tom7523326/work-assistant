# 寿哥29天Vibe Coding整课制作工作流

适用于“开始Day14”“继续本期下一步”或授权整期制作。Day13是方法基线，课题、时长、计数、素材、界面与授权按本期重新确定。所有阶段在当前 `DayN_制作状态.json` 留可接续记录。

## 0. 确认本期起点

读取当期状态、用户最新修改、权威v9框架和上一期最终工程；确认上一期真实具备哪些功能。只借用方法，不把上一期检查结果算成本期通过。

新一期按需运行初始化脚本；已存在目录安全接续。不要清空目录，不默认开始付费或发布。制作状态至少记录：当前阶段、已审素材、修改要求、工程基线、实际检查、当前期授权和发布状态。

工具环境按实际发现：Chrome承载已登录NotebookLM、Gemini/Nano Banana、HeyGen和抖音后台；本地工程/真实录屏/FFmpeg承载可复验制作；剪映可审看或剪辑。Day13验证了本地合成导出，未形成最终剪映多轨模板。

## 1. 任务卡与思维导图

**输入**：本期框架、上一课工程与真实卡点。

**产物**：`DayN_任务卡.md`；`DayN_课程思维导图.md`及可预览PNG/SVG或可导入文件。

包含以下内容：
- 整体目标：观众完成后能做什么，输入、动作和结果。
- 面向人群与前置能力；第一次刷到本视频的人从哪里开始。
- 预计正片与练习时长。以讲清任务为准，5–8分钟是初始参考；Day13精剪3分39.68秒不是时长模板。
- 开头先给可见结果或前后变化，再用一句话说清本课任务。
- 各章节：时间预算、呈现要点、具体画面、口播要说的事、对应跟做动作。
- 至少一个常见错误/例外和可观察验收；作业、行业迁移、下一课承接。

可用章节顺序：结果前置 → 目标和起点 → 输入准备 → AI实现/真实演示 → 排障 → 验收 → 作业迁移。按内容调整，不机械凑七段。

**审定标准**：一个核心行动链；结果能在实际工程复验；新手知道用什么材料和怎样做；不提前承诺未实现功能。文字稿、可视导图、用户审定分别记录；只有文字草稿时不能记整步已交付或已审定。

## 2. NotebookLM统一课件

**输入**：已审导图文字、必要技术来源、往期认可的视觉参考。视觉参考只提取风格，不把旧课题带入本期。

用用户已登录Chrome建立/接续当期NotebookLM，导入来源。生成前明确：29期、DayN、寿哥本人及有依据的资历、本期目标和画面结构。记录真实项目入口、生成状态和导出文件。

可直接调整使用的提示词：

> 根据本期课程思维导图，制作一套供数字人口播配合使用的16:9横版课件。沿用上传往期参考的纸张质感、手绘元素、字体层级和配色；全套视觉一致。每页讲一个要点，主标题短，展示具体输入、操作、结果和验收，避免长段文字。开头先展示本课完成后的变化，随后明确观众从什么起点跟做。保留跟做、验收、作业和行业迁移。准确使用“29天带你玩转Vibe Coding / DayN”，不得编造个人成绩或经历。背景完整铺满，底部不留大白栏，不画头像占位灰圈。给字幕和左下偏上的本人圆窗留可用空间，但用连续背景承载，不加空白框。正文不要解释内部制作流程。只用已提供和已核实的内容。

下载PPTX/可用原始格式，渲染为逐页图片审查文字、数量、比例和留白。缺页优先NotebookLM同风格单页；能力不支持时在Gemini/Nano Banana提供已认可页面作为视觉参考，补同风格图，不另起一套PPT设计。

**审定标准**：手机大小能读；没有伪造数字/乱码；每个主要动作有画面；全片风格一致；无大白框/旧圆圈/空白底带。课件导出完成才记已下载，不以预览截图代替源文件。

## 3. 寿哥口语逐字稿

调用现有 `$shouge-spoken-script`，读其口语指南并按题材选择前12期样本。以已审导图与课件起稿，不把内部核验说明读进正文。

产物：有自然段与画面锚点的MD + **只有实际可读正文**的TXT。技术发音、分镜、提示词和注释另放。画面锚点记录“说到这句出现哪个结果”，避免按PPT页数机械分配口播。

语言要简洁、干净、能顺口说；开头直接给具体变化。“不提隔了三个月/复更”的反馈沿用。UTF-8等英文术语可在提示词或画面保留准确写法，口播用“表格中文不乱”等自然解释。不是一律删技术内容，也不让关键编码规则缺失。

口语Skill起稿后，用Gemini当前账号可用的最高推理深度进行二审，按 [Gemini审稿规则](gemini-script-review.md)保存原始意见和采纳判断，再完成稿件审定。不能把未获得的审查结果写成已完成。之后再做完整数字人。稿子里的功能、保存行为和验收数字在下一步工程实测后冻结；实测有差异时修正文稿和课件，避免生成后才发现事实错误。

**审定标准**：没有AI说明书腔、冗余转场或未经核实的亲身经历；“你看这条/点这里”都有对应画面；时长只是估读，直到有真实音轨才记实测。

## 4. 真工程、跟做包与真实演示

从上一课最终版本复制出当期起点，在独立副本做真实修改；不改坏已发布上一期。保留需求输入、改动差异、运行结果和检查证据。终点演示是功能实操，不冒充完整AI生成录屏。

跟做包最少包含：可启动起点、参考终点、虚构/脱敏样例、完整跟做提示词、3步启动说明、已知限制。运行依赖尽量沿用；对未接触前12期的学员给必要补课入口。

先做正常路径和一个关键例外，再录关键操作：输入/导入 → 操作 → 可见变化 → 验收。真实页面录屏可按事件自动化，但新一期重新制定选择器、数据和独立预期。静音录像，旁白由本人声音承载；剪等待，保留能看懂的点击和结果停留。

必要时添加教学浏览器框与“Vibe Coding产物：网页工具”等说明。说明应帮助观众识别结果，不伪造真实地址栏或显示AI建造全过程。字和按钮太小就局部放大或换焦点。

**审定标准**：数量、字段、状态和功能与口播一致；错误提示真实出现；实际运行与未运行检查分别记录；从发给学员的起点能完成任务。作者自测不等同外部学员试用。

## 5. 本人数字人口播与动态片头

核对当前期使用已购额度的授权。HeyGen选择当时满足画质/本人身份/声音要求的最低合适档；Day13用Avatar III，不能据此假定今后价格和扣点不变。记录实际选择及可见扣点，不编造单片成本，不自行续费或买追加额度。

用已确认的寿哥数字人与声音；Day13正常语速speed=1可作初始参考，最终以当期试听为准。先通过不额外超出已授权成本的预览/短试听检查关键发音，再整段生成；没有免费试听不假称可免费试。词音不对时优先换自然说法或局部修订，实操与关键定义不能因此误删。

下载原片保留。记录实际读出的正文；识别漏句、语速、口型和发音。ASR是核对辅助，需要听查可疑项；原稿写过的句子不等于音轨真的读过。

Gemini片头提示词框架：

> 生成与16:9横版课程匹配的动态开场。视觉表达“[本课前状态] → [本课可见结果]”，保留寿哥系列的配色和元素，前几秒主体醒目。尽量不用生成中文小字或复杂伪造UI；关键文案后期添加。按可用模型生成短素材。人物出现时只用已提供的本人参考；这是视觉片头，后期使用既有口播，不采用生成声音。

生成长度与最终用量分别记录。挑能完整接住钩子的片段；Day13约10秒原片只用前7.2秒是本课选择，不是通用时长。

## 6. 合成、字幕与审片

读取 [媒体制作与审片](media-production.md)。先冻实际口播音轨，再对齐字幕与画面；数字人画面和口播使用同一剪切决策。删任何段落都同时重排音频、头像和字幕。

导出MP4及SRT，保留时间轴、源素材与渲染命令/环境。新时间轴的圆窗位置来自本期制作状态中的layout，不能沿用Day13右下的旧坐标。先做代表性的2秒片段验证画幅、左下头像贴合、字幕位置，再渲染全片。导出后检查手机抖音常规播放、横屏全屏及账号/互动控件出现时的遮挡。

给用户提供可实际播放的成片，落实反馈。对“全片头像都放这么大”这类全局要求检查所有镜头；不只修一个截图时点。保留旧版，不把旧抽查图当最终证据。

**审定标准**：满幅、无黑边/大白栏；统一头像填满圆窗；字幕准确且同步；关键实操手机可读；删段无残句；生成片头无原声；正常解码。视觉审查、实际听审和程序检查分别记结论。

## 7. 三比例封面

视频首图16:9；当前Day13抖音横封面4:3、竖封面3:4。每期上传前读实际后台要求，三种比例分别排版生成。

可用提示词：

> 使用上传的寿哥本人照片/已确认数字人作为唯一身份参考，保留本人面部特征与自然表情。参考认可的绿黑/荧光绿高对比宣传风格，围绕“[具体痛点] / [本课做出的工具和成果]”制作[16:9或4:3或3:4]封面。为该比例从头安排标题、本人、成果界面和辅助文案，不能把其他比例横图直接裁切或拉伸。主标题最多两行，成果可一眼认出，中文完整正确。本人和工具主体都不出边，预留后台安全边距。系列标识写“29天带你玩转Vibe Coding · DayN”。

先核对本人身份、中文、成果对应，再上传两个抖音比例。Day13后台PNG上传未生效，换JPG才成功，这只是已观察兼容性；上传无变化时先核对文件/格式，禁止反复提交同一素材。

**审定标准**：尺寸/比例准确；人物确为本人；横竖各自布局完整；后台分别显示新缩略图；视频首图与后台封面分别记录，不能拿一个替代另一个。

## 8. 发布文案与文本评论

制作可审看的标题、正文、标签和评论提示词。标题用具体痛点+可见成果或数量变化，写能履行的收益，不保证爆款。正文给跟做入口和作业；明确内容由AI生成的状态按实际素材与平台入口设置。

核对当期发布授权后上传/提交。沿用已审封面和最终文件；表单预览核对标题、正文、两个比例、声音/画幅、声明。提交后读回后台/作品URL，记录“上传中/审核中/已发布/修改审核中”，不把提交成功说成审核通过。遇网络或超时先查看服务器/页面实际状态，避免重复发布。

评论默认**只有文本提示词**：先说明输入/列名，再讲限定范围、三个操作、错误提示与量化验收，最后要求AI报告实际检查。编码准确写在文字里；不加外链、网盘、二维码或引导站外下载。可补虚构样例文字，但不以资料包名义发内部证据。发布评论需当前期授权，发布后读回作者与完整内容，避免重复发。

## 9. 归档与下一期

写最终交付说明与制作状态：版本、视频参数、源材料、真实验证/未做项、当前发布与封面审核状态、作品URL、评论正文、下一期工程起点。私有材料与公开素材明确标记；不因为本地打了ZIP就公开网盘。

将本期返工沉淀到对应规则，不无限加通用禁令。风格样本只有用户明确认可的新稿/已发布成片才能进入口語Skill，未验收AI稿和测试件不进入本人语料。

发布数据只按用户要求复盘。若用户要后续监测，另遵循自动化工具建立任务；没有要求时不自设提醒/定时发布。
